## 一、SM3 算法大致原理

SM3 是中国国家密码管理局发布的密码杂凑函数标准，类似于 SHA-256，主要用于信息安全领域的数据完整性保护和数字签名。

SM3 的核心流程包括：

1. **消息填充**  
   输入消息首先按照特定规则填充，使得消息长度满足 512 位（64 字节）的整数倍，且填充后消息长度信息被附加。

2. **消息分组**  
   将填充后的消息分割成若干个 512 位的消息块。

3. **消息扩展**  
   对每个消息块生成 68 个 32 位字 `W[i]` 和 64 个 32 位字 `W1[i]`，这是消息调度部分，用于后续压缩函数计算。

4. **迭代压缩**  
   利用八个 32 位寄存器（`A, B, C, D, E, F, G, H`）初始化状态值，针对每个消息块执行64轮迭代运算，通过布尔函数、置换函数和轮常量，混合消息调度生成的 `W` 和 `W1`。

5. **输出结果**  
   所有消息块迭代完成后，将最后的状态值拼接形成256位（32字节）的哈希值。

SM3算法设计确保了抗碰撞性和雪崩效应，是一种安全的哈希算法。

## 二、SM3 算法优化思路说明

在原始SM3实现基础上，我尝试了以下几方面的优化：

### 2.1. 减少不必要的内存拷贝

- 通过直接使用`uint8_t`指针操作输入数据，避免中间临时数组的重复构造和拷贝。
- 预先分配好消息和哈希缓存，避免动态扩容带来的性能开销。

### 2.2. 减少函数调用开销

- 将部分小的内联函数（例如`ROTL`、`P0`、`P1`）使用`inline`修饰，降低函数调用成本。
- 采用简单的宏或内联函数替代复杂的函数结构。

### 2.3. 批量处理逻辑封装

- 设计批量处理函数`sm3_batch`，减少循环控制逻辑开销，提高代码结构清晰度。
- 对消息处理进行连续内存访问，提升缓存局部性。

### 2.4. 使用合适的编译优化选项

- 编译时使用`-O3`开启最高等级优化，自动进行循环展开、指令调度等。

### 2.5. 预计算常量和减少冗余运算

- 使用静态`constexpr`数组存储轮常量`T[i]`，避免运行时计算。
- 合理设计消息扩展算法，减少重复计算。

## 四、基于 SM3 算法，验证长度扩展攻击的思路

在SM3算法中，长度扩展攻击（Length Extension Attack）是一种典型的攻击方式，适用于使用Merkle-Damgård结构的哈希函数（如MD5、SHA1、SHA256、SM3）。攻击者在不知道消息内容的前提下，只知道 hash(message) 和消息的长度，便能构造 hash(padded(message) || suffix)，从而伪造带认证的新消息。

由于 SM3 采用 Merkle–Damgård 构造，处理消息块时使用中间状态（即哈希值）作为初始向量（IV）继续计算，因此攻击者可以利用 SM3(M) 作为新的 IV 来追加消息 M’。

**攻击前提**：攻击者知道 hash(m) 的值，即 digest；攻击者不知道 m 的原始内容；攻击者知道 m 的长度（或猜测范围）

**攻击目标**：攻击者想要伪造 m || padding(m) || suffix 的哈希值。

**攻击思路**：已经有一个 SM3 类，并支持从头计算 SM3::hash(data, len, digest)。要实现 length extension attack，攻击者还需提供一个新的 hash_with_iv(data, len, digest, iv) 接口，能让攻击者用已有 IV 作为初始状态压缩。此外，攻击者还需要模拟 SM3 的 padding，加上 suffix 后再继续 hash。

因此，我们可以构造攻击伪造流程：真实用户计算 hash(m)，攻击者获得 digest；攻击者伪造 hash(m || padding(m) || suffix)，并用它来伪造消息签名。

## 六、基于 SM3 算法的 Merkle 树的构造，并证明叶节点的存在性

### 6.1. 约定（哈希定义 / 编码规范）

   设哈希函数为 H(⋅)（本文用 SM3，但所有描述与哈希函数无关）。

   叶子哈希（LeafHash）：$LeafHash(D)=H(0x00∥D)$

   即在叶子数据前加单字节前缀 0x00 再哈希。

   内部节点哈希（NodeHash）：$NodeHash(L,R)=H(  0x01 ∥ L ∥ R  )$

   即在左子哈希与右子哈希前加单字节前缀 0x01，再拼接哈希并哈希。

   这样的前缀能避免叶子/内部节点哈希的二义性（防止拓展攻击）。

### 6.2. RFC6962 的递归划分（关键点）

RFC6962 定义的 Merkle Tree 不是简单向上补齐到最近的 2 的幂，而是用分治的方式按区间递归计算根：
给定区间长度 n>1n>1，将区间划分成左区间长度 k 和右区间长度 n−k，其中$ k=2⌊log⁡2(n−1)⌋$

（即「小于 nn 的最大 2 的幂」）。然后就有：
$ MTH(D[0:n])=NodeHash(MTH(D[0:k]),  MTH(D[k:n])) $

当 n=1 时，MTH 就是该叶子的 LeafHash。

举例：n=5 时 k=4，把前 4 个作为左子树，剩下 1 个为右子树；n=4 时 k=2 等等。

### 6.3. Merkle 根（MTH）构建算法（伪代码）
```
function MTH(leaves[0..n-1]):
    if n == 0:
        return H(empty)                 // RFC 的处理可按实现，或定义为空哈希
    if n == 1:
        return LeafHash(leaves[0])
    k = largest_power_of_two_less_than(n)  // eg. k = 2^{floor(log2(n-1))}
    left = MTH(leaves[0..k-1])
    right = MTH(leaves[k..n-1])
    return NodeHash(left, right)
```

若实现为自底向上两两合并（更常见于工程实现），需注意 RFC 的特定划分规则；常见工程实现将叶子分层合并，但需保证最终树与 RFC 定义一致（使用相同的划分策略或等价构造）。

### 6.4. 生成存在性证明（Inclusion / Audit Path）

目标：给定叶子索引 m（0-based）和整棵树大小 n，返回一组哈希值 path，验证者能用目标叶数据与 path 重建出根哈希。
生成思路（递归）

在递归计算 MTH 时，若目标 m 在当前区间左半部分，则递归进入左子区间并将 右子树的 MTH（即 sibling subtree hash） 加入 path；反之亦然。

path 的顺序必须与验证方的重建规则一致（通常从底层向上追加兄弟节点哈希）。

伪代码如下：
```
function build_path(m, l, r, out):
    // builds PATH(m, D[l:r]) and appends sibling subtree hashes into out
    if r == l + 1:
        return
    len = r - l
    k = largest_power_of_two_less_than(len)
    if m < l + k:
        build_path(m, l, l+k, out)
        out.append(MTH(l+k, r))    // append the hash of the right sibling subtree
    else:
        build_path(m, l+k, r, out)
        out.append(MTH(l, l+k))    // append the hash of the left sibling subtree
```

**验证（从 path 重建 root）：**

验证者先计算 cur = LeafHash(data)；然后按与生成时相同的递归顺序，消费 path 中的哈希值，逐步合并成更高层的节点哈希，直至得到根哈希；最终比较重建根与公开的 Merkle 根是否相等

**复杂度：**

生成一个包含证明的时间复杂度在没有缓存子树哈希的情况下为 $O(n)$（因为递归计算可能需要计算许多子树哈希）；如果缓存子树哈希（或采取自底向上构建整个树），构建与查询单个证明都能降到 $O(logn)$（相对于树高度）。

证明大小（路径长度）约为树高度，最坏情况下 $⌈{log_2n}⌉$ 左右（RFC6962 的分割可导致略大于 $log_2​n$，但同阶）。

### 6.5. 不存在性证明（常见实用方案：邻居包含证明）

RFC6962 本身主要定义了包含证明与一致性证明；不存在性证明没有单一定义。以下是工程中常用且简单的做法 —— 基于排序后邻居证明：

**前提与假定：**

1. 叶子集合按某种确定性顺序（最常见：字典序或按叶子哈希排序）保存在树中。

2. 验证者与出证明者对排序方式有共同认知。

**算法思路：**

对目标 X，在叶子序列上做二分查找，找到其应插入位置 idx（使得 leaves[idx-1] < X <= leaves[idx]）。

若存在 idx-1（predecessor），生成 predecessor 的包含证明；若存在 idx（successor），生成 successor 的包含证明。

将 predecessor、successor（任一个或两个）连同它们的包含证明一起返回。验证者： Merkle 根；比较被证明的叶子值与 X，确认它们确实不是 X，且 X 在两者之间（或在极端端点）；从而断定 X 未出现在集合中。

伪代码如下：
```
function non_membership_proof(X):
    idx = lower_bound(sorted_leaves, X)
    proof = {}
    if idx > 0:
        proof.pred_index = idx - 1
        proof.pred_path = get_audit_path(idx - 1)
    if idx < n:
        proof.succ_index = idx
        proof.succ_path = get_audit_path(idx)
    return proof
```

**验证方检查：**

    使用 pred_path / succ_path 与对应叶子数据重建并比对公开的 Merkle 根。

    若证明有效且被证明的值与 X 不相等，并且 X 落在它们之间（或在端点不等），即可接受 X 不存在。

**复杂度：**

二分查找：$O(log(n))$

每个包含证明验证：$O(log(n))$

总体：$O(log(n))$

**局限：**

该方法依赖于叶子有序（或可被排序）；若叶子按插入顺序存储且无外部索引，则无法直接用此方法。

若想获得严格短的、不依赖全序的不存在性证明，应采用例如 稀疏 Merkle 树（Sparse Merkle Tree） 或 authenticated dictionary 等结构，它们能提供小且确定性的非存在证明（例如表明某个 key 的树叶为默认值）。

## 八、总结

本项目完整实现了国密SM3哈希算法，严格遵循其核心流程：消息填充至512位倍数、分组处理、消息扩展生成68个调度字，以及64轮迭代压缩。在基础实现之上，通过多维度优化显著提升性能：采用直接内存操作消除数据拷贝开销，关键函数内联化（ROTL/P0/P1）减少调用损耗，设计批量处理接口增强缓存局部性，并预计算轮常量表避免运行时重复运算。配合-O3编译优化，最终实现吞吐量的大幅跃升，实测性能对比显示优化后速度提升显著，充分验证了优化策略的有效性。

我们还基于SM3的Merkle-Damgård结构特性，成功实施了长度扩展攻击实验。攻击利用已知哈希值作为初始向量（IV），通过精确模拟填充规则（附加原始消息长度）和新增```hash_with_iv()```接口，实现了对"原始消息||填充||恶意后缀"的哈希伪造。攻击结果证明：即使不知原始消息内容，仅凭哈希值和长度信息即可构造有效的新消息认证码。这一实验不仅复现了经典攻击模式，更揭示了SM3在特定场景下的安全边界，强调了在数字签名等应用中必须采用HMAC等加固方案的必要性。

此外，我们基于SM3构建了符合RFC6962规范的Merkle树，通过前缀编码解决节点二义性（叶节点```H(0x00||data)```，内部节点```H(0x01||L||R)```）。采用递归分割策略（$k=2⌊log₂(n-1)⌋$）处理非2ⁿ数据规模，实现高效树形结构。在存在性证明方面，生成$O(log n)$大小的审计路径（兄弟子树哈希序列），验证端可逐层重建根哈希；针对不存在性证明，创新采用有序叶子的邻居证明方案，通过前驱/后继叶子的包含证明及数值比对确认缺席。实验结果验证了该体系在数据完整性验证场景中的完备性与实用性。
